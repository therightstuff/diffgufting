# Testing

Development uses Node.js's built-in test runner through `scripts/test-runner.mjs`. `npm test` runs `tests/*.test.mjs`; `npm run test:desktop` runs the desktop suite. The wrapper writes full stdout/stderr logs plus an atomic terminal report and compact status record under `test-results/runs/`, while its terminal output stays limited to the run outcome and artifact paths. A passing run exits zero and reports no failures. Tests own disposable filesystem/repository fixtures and clean up only their fixtures.

Run `npm run test:performance` for the performance model suite. For a focused native Node selection, use `npm run test:focused -- --test-name-pattern='pattern' tests/file.test.mjs`; it remains behind the same wrapper. Query a completed run without replaying logs using `node scripts/test-runner.mjs --status RUN_ID`; use `--artifact-dir DIRECTORY` to place artifacts elsewhere. Add `--verbose` to stream child diagnostics, or use `--failure-details RUN_ID` for the bounded trailing failure excerpt. Without compatible timing history, the status response recommends polling after 10 seconds.

The desktop runner executes Playwright/Electron integration tests in `tests/desktop/`. Those tests require the built renderer, installed Electron runtime, and a graphical desktop. The packaged-app test additionally requires `npm run package -- darwin arm64` on macOS Apple Silicon. CLI process-lifecycle tests currently use macOS process inspection and explicitly skip other operating systems. Tests launch and close only their own application instance. Platform results distinguish completed checks from unavailable platforms.

Current focused suites cover document transitions and review, CLI/source parsing, filesystem comparison and guarded saving, monotonic source-load progress, Git layer snapshots and immutable absent paths, scoped watcher reconciliation, atomic replacement, cache eviction, workspace limits, and Device theme state. The desktop suite covers editing, disjoint contention review, layout switching, undo, theme selection, and commit-picker ref labels, and writes a screenshot under ignored `test-results/`. Run `npm run build` before desktop tests. Teardown exits the owned test application directly so disposable unsaved buffers do not block cleanup.

Additional desktop cases cover three-way merge results, close cancellation, Git category gutters, the browser host boundary, long-document scrolling/selection, and the packaged macOS application. [Verification results and remaining platform checks](verification.md) record the completed runs. Set `DIFFGUSTING_SETTINGS_DIR` to an isolated directory when a test needs independent preferences.

Workspace model checks live in `tests/workspaces.test.mjs` and `tests/navigation.test.mjs`; Git source identity cases extend `tests/git.test.mjs`. `tests/desktop/workspaces.test.mjs` covers comparison switching, recent-menu data, explicit Git choices, source labels, dirty circles, synchronized merge navigation, and highlight styling. Build first, then run selected desktop files serially with `npm run test:focused -- --test-concurrency=1 tests/desktop/editor.test.mjs tests/desktop/workspaces.test.mjs` so graphical instances do not compete for keyboard focus. A successful run reports zero failures; merge navigation also writes `test-results/workspace-merge-navigation.png`.

`scripts/export-icons.mjs` exports PNG sizes plus ICO/ICNS containers using Sharp. `scripts/build-app.mjs` bundles the renderer with esbuild. `scripts/package-app.mjs` uses Electron Packager and the host's `zip` executable to assemble a distribution. Their npm commands are documented in [setup](setup.md). Successful scripts exit zero and print the paths or sizes they produced.

`scripts/generate-comparison-fixtures.mjs ROOT [SEED] [SCALE]` creates deterministic paired folder fixtures and a versioned manifest. Pass a disposable directory as `ROOT`; the caller owns its cleanup.

`scripts/run-comparison-benchmark.mjs` exports `runBenchmark({ candidates, fixture, cacheMode, warmups, repetitions, timeoutMs })`. Candidates receive `{ fixture, cacheMode }`; setup runs outside measured samples, candidate order alternates, and a timeout is recorded as a failed measurement. Persist reports with `writeBenchmarkReport`; compatible comparisons require identical fixture and effective settings. Reports include version, environment, fixture/configuration identity, raw samples, median/p95 summaries, correctness, failures, and unavailable measurements. Wrapper artifacts distinguish fresh application-cache runs from reused cache runs; operating-system filesystem cache state is not controlled and must be recorded by the caller. Comparison-cache snapshots expose only byte-bounded text/hunk entries and their key/version identity; inventory metadata is retained only by its open comparison.

`scripts/benchmark-enumeration.mjs` supplies equivalent `readdir` and buffered `opendir` candidates for the versioned wide/deep fixture shape. The application uses the `readdir` traversal with effective defaults of eight directory operations and batches of 100 inventory entries; candidate results are correctness-checked before comparing latency.

Git directory sources retain object IDs in their inventory and retrieve one selected blob at a time. The selected-entry path avoids bulk blob transfer, so no blob batching is enabled unless a future compatible benchmark demonstrates a need.

For long runs, query `--status` instead of reading a log. Status records expose the compact outcome, elapsed time, timing-history availability, and recommended polling interval. `--failure-details` returns at most 1 KiB of the final combined test output; missing or corrupt artifacts fail with an explicit diagnostic rather than replaying a log.

Run `npm run test:stress` for stress-profile validation. `scripts/comparison-stress-profiles.mjs` declares bounded default and 10,000-leaf profiles plus an explicitly opt-in 100,000-leaf profile. The desktop profile requires Electron; unavailable platform/runtime conditions are reported as skips, never as zero measurements.

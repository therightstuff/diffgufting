# Architecture

Diffgufting separates document state from presentation. Shared models live in `src/core/`, host filesystem and Git adapters in `src/host/`, the Electron bridge in `src/desktop/`, and the portable renderer in `src/ui/`. The CLI belongs in `bin/` and build/distribution entry points in `scripts/`.

`scripts/test-runner.mjs` owns the common test execution contract. It streams child diagnostics to unique ignored artifacts, writes atomic terminal and compact status JSON records, and retains bounded compatible successful-run timing history. Package test commands invoke it before Node's test runner, including serialized desktop execution.

The shared document model owns buffers, disk baselines, observed external versions, and bounded in-memory undo/redo. All content replacements pass through its journal. The journal groups adjacent typing, backspace, and forward-delete transactions for less than five seconds, while commands, transfers, merges, reloads, and replacements remain isolated. It updates text and the collapsed primary selection atomically for undo and redo. Themes and layouts consume shared documents rather than owning independent copies. Repository objects and index snapshots are read-only; merge results are ordinary files.

The generated PNG masters in `assets/branding/` own the visual identity. Their source reference and generation prompts remain alongside them; platform exports derive from the icon master.

## Comparison workspaces

`src/host/workspaces.mjs` retains sessions by ordered path-and-revision identity. A New draft loads its two sources independently and is listed from the first source selection, with its label updated on source-state changes. Explicit submission or changing a completed pair registers its exact identity; direct CLI and Recent requests continue using direct open. Source metadata captures fixed base commits and matching branch/tag labels, including annotated tags. Working buffers remain keyed by canonical path; immutable buffers include repository, scoped path, and revision identity. Recent comparisons store a versioned list of up to 10 unique source descriptor pairs in `recent-comparisons.json`, independently of preferences and document history.

`src/core/navigation.mjs` maps positions across differences, using corresponding unchanged content or the nearest change boundary. `src/ui/navigation.mjs` coordinates active source, base, and result panes, guards propagated selection/scroll updates, and renders the right-side overview. Propagated navigation does not create document transitions or move keyboard focus. Comparison records retain layout, selected file, display aliases, and navigation state independently of shared document buffers.

`src/core/incremental-diff.mjs` owns bounded, versioned comparison results. Known one-range edits update CodeMirror chunks and derive exact changes from those chunks rather than re-diffing the same document pair. `src/core/change-layers.mjs` retains immutable Git layer differences while mapping them onto the current working text. `src/core/scoped-update.mjs` lets mounted secondary editor views apply a verified local delta; transitions without a matching predecessor retain a full-document fallback.

Workspace events identify the owning session, and the renderer ignores inactive sessions' source/comparison updates while continuing to observe shared disk changes. Source generations also reject obsolete inventory and history updates. Explicit draft submission requires a completed result for two ready, type-compatible sources. The host validates typed paths and historical absent-source types. Open-comparison revision replacement loads a separate candidate, activating it only after success; duplicate identities activate their retained record. Reads and saves route to a session that authorized the document. Successful saves update all observing session baselines to avoid treating the application's write as an external conflict.

Canonical locations, type, repository, and base/output scope seed independently opened groups. Source replacements explicitly carry the invoking group, so path and revision changes never split that workflow. Exact identities deduplicate within the invoking group; an identical pair in another group retains a separate session while writable documents share canonical-path buffers. New/CLI/Recent preserve global exact-pair reuse. Each group owns members and a visit cursor, published with its current member ID. Back/Forward only moves that cursor; direct activation truncates forward visits without closing members. Closure removes all visits after renderer dirty protection and chooses a surviving prior visit. Groups and visit histories are session-local.

The renderer keeps New as an unregistered creation page; selecting it hides the active comparison without removing retained sessions, buffers, or group cursors. Root paths remain editable through typing/Browse alongside version comboboxes in every layout. The collapsible bottom-third sidebar renders one slot per group from its current member ID, even while New is displayed. Each slot has a current-member close button but no history dropdown. Back/Forward arrows in the top source panel navigate the active group's cursor, remaining disabled on New and at history boundaries. Folder list/tree rows use a fixed-height, overscanned viewport window over the current inventory; scrolling reveals the next range without extra range requests. Path anchors, filtering, expansion, and selected entries belong to the comparison. Generation and workspace checks discard obsolete lazy-entry replies.

New, Recent, and sidebar activation retain loaded drafts in a separate host map and publish them as selectable sidebar entries without registering an exact comparison identity. Their sessions and renderer document ownership survive navigation, including when both folder sources have loaded and child files have been edited. Submission removes the retained draft entry and registers or deduplicates the exact pair. Empty drafts can be disposed during navigation. Explicit closure and destructive source/type changes retain dirty-document protection; disposing a draft releases only its final document references. Scoped source events are the sole source-state update path, so a late IPC reply cannot overwrite another comparison. Native window closure asks the ready renderer for current dirty state rather than relying on a potentially delayed notification; a crashed renderer does not prevent closing the window.

## Host contract

The isolated preload exposes bootstrap, retained comparison open/activate/close, recent reopening, independent source loading, source state, source selection, history paging/closing, immutable commit selection, read, save, save-as destination selection, refresh, preferences, About-link opening, dirty-state notification, and close approval. Requests return `{ok, value}` or `{ok: false, error, external?}`. Bootstrap includes package-derived application identity (name, version, description, logo, repository, and support URL); the host alone opens the two configured HTTPS links. Bootstrap and preference responses include persisted preferences and the resolved light/dark appearance. The Electron host applies the persisted `dark`, `light`, or `system` theme source before showing a window, then publishes resolved appearance updates while Device mode is selected. Save requests include a path, text, expected fingerprint, and encoding/newline format. The host authorizes writes only to documents opened by a loaded source or through the native save dialog. Events carry source states and progress, comparison results, repository-discovery availability, resolved appearance, observed disk versions, monitoring errors, menu commands, or close requests.

Source descriptors are `{kind: 'file', path}` or `{kind: 'git', repo, ref, path}`. Each side owns a descriptor, generation, loading state, estimated progress, loaded tree, and optional selected-path repository record. Filesystem discovery and sorting run in a worker thread, and the same inventory constructs the lazy source tree without another directory walk. Inventory events contain only new entries with an append offset, bounded by `inventoryBatchSize`; the host retains metadata on the source without repeatedly sorting, caching, or transmitting growing prefixes. The renderer appends these deltas and coalesces file-list rendering to animation frames. Cancellation carries no repeated entries, and generation checks reject stale batches.

Byte verification supplies row status, while the selected-entry bridge authorizes and reads editor text/hunks on demand. A separate comparison worker consumes ready trees and generation checks discard obsolete source or pair results. Comparison-owned, byte-bounded caches retain fingerprint, pair-result, and hunk entries separately from source inventory and dirty document ownership. Comparison results contain left/right trees, optional base/output, relative-path rows, and independently labeled Git layers. File entries carry content, fingerprint, editability, format, and an explicit unavailable state. History sessions capture branch, tag, and HEAD tips, stream bounded topological pages through opaque cursors, and retain graph lanes across rendered pages; selecting a commit reloads only the original repository-relative path.

## Observation and history

The host watches source directories and reconciles affected paths after a short debounce; a watcher failure falls back to periodic root refresh. It fingerprints file contents, suppresses verified self-save events, and serializes writes per document. The renderer's shared document registry prevents duplicate independent buffers for the same canonical path. All persistent document edits use a delta journal with versioned local ranges; pending review snapshots remain separate from evictable undo entries.

Defaults are registered in `src/core/settings.mjs`: 100 MiB history, a 5-second undo grouping pause, 2-second reconciliation, 100-millisecond watch debounce, 30-second operation timeout, and 32 MiB editable file limit. Preferences contain configuration only, never document history. The portable UI depends on the host contract rather than Node or Electron APIs.
